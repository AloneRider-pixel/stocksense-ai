# StockSense AI Architecture

StockSense AI is structured as a market-intelligence product with explicit boundaries between the web client, API, market-data ingestion, ML evaluation, persistence, asynchronous jobs, and operational telemetry.

## Market-data ingestion

1. Provider fetches daily OHLCV bars.
2. Provider adapter validates and normalizes them into the internal MarketBar contract.
3. Market bars are upserted into PostgreSQL by symbol and trading date.
4. Pending predictions are reconciled against the first later market bar.
5. The API serves stored data and refreshes it when the latest ingestion is stale.

## ML evaluation

Training constructs only backward-looking features and a next-period target. Walk-forward validation uses expanding historical windows and later observations for evaluation. Every out-of-sample prediction is retained with its actual value so model behavior can be audited observation by observation.

## Data ownership

PostgreSQL is the system of record for users, market bars, and predictions. Redis is a performance and job-coordination layer; cached state can be regenerated.

## Model lifecycle

    Data → Features → Walk-forward evaluation → Final fit → Registry → Prediction API

Generated model binaries, metrics, and evaluation CSVs are intentionally excluded from Git and regenerated by the training workflow.
